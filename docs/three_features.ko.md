# Lost Tokens의 생성 예산과 분기 제어

Lost Tokens는 선택되지 않은 추론 분기를 컨텍스트 메모리로 재사용하는
학습 없는 디코딩 방법이다. 기존 main의 알고리즘에 세 가지를 추가한다.
32K 생성 예산 안에서 답변 구간을 확보하고, 엔트로피가 높은 위치에서
분기하며, 분기 탐색을 문장 경계에서 조기 종료한다.

## 기존 알고리즘

`<think>` 안에서 최소 한 토큰을 생성한 뒤 분기 가능성을 확인한다.
원래 다음 토큰 분포에서 확률이 0.20 이상인 일반 토큰을 모두 후보로
삼는다. 후보가 두 개 이상이어야 하며, 가장 확률이 높은 토큰이 특수
토큰이면 분기하지 않는다. 분기 간격은 본문 생성 토큰 기준 256이다.

각 후보는 같은 부모 KV 캐시를 독립적으로 복사해 최대 32토큰을 탐색한다.
가장 확률이 높은 후보를 선택하고, 선택되지 않은 후보 중 코사인 유사도
필터를 통과한 텍스트를 `<possibilities>` 메모리로 넣는다. 그 다음 선택된
롤아웃의 토큰을 그대로 본문에 커밋한다. 메모리 압축은 오래된 메모리
블록만 제거하며, 생성된 본문은 보존한다.

## 추가하는 세 가지 규칙

### 1. 32K 안에서 답변 구간 확보

본문 생성 한도는 32,768토큰이다. 추론이 본문 31,743토큰까지 열려 있으면
`</think>` 한 토큰을 삽입해 추론 구간을 닫는다. 남은 1,024토큰은 최종
답변에 사용한다.

```text
추론 31,743 + 종료 경계 1 + 답변 최대 1,024 = 본문 최대 32,768
```

본문 청크뿐 아니라 모든 후보 롤아웃의 길이도 남은 추론 예산으로
제한한다. 따라서 선택된 롤아웃을 그대로 커밋해도 강제 종료 지점을
넘지 않는다. 추론이 자연스럽게 먼저 종료되면 강제 토큰을 넣지 않고
기존 본문 한도 안에서 답변을 생성한다. EOS가 먼저 나오면 즉시 끝낸다.

이 제한은 **본문 생성 토큰**에 적용된다. 입력 토큰, 주입된 메모리,
선택되지 않은 분기의 탐색 비용은 별도로 센다. 보장하는 것은 토큰
한도와 열린 추론 구간의 종료다. 예약된 토큰 안에서 답변을 완성하거나
정답을 내는지는 모델의 출력 결과로 평가한다.

### 2. 엔트로피 기반 분기

전체 어휘의 원래 다음 토큰 확률 분포에 대해 Shannon entropy를 계산한다.

```text
H = -Σ p(token) log p(token)
분기 조건 = 기존 후보·특수 토큰·간격 조건 충족 AND H ≥ 0.65 nats
```

엔트로피는 temperature나 top-k/top-p 샘플링 필터를 적용하기 전 분포에서
계산한다. 수학·객관식 구분 없이 같은 기준을 적용한다. 숫자나 연산자가
포함되었다는 이유로 엔트로피 기준을 우회하지 않는다.

### 3. 문장 경계에서 분기 탐색 조기 종료

분기 롤아웃은 기본적으로 최대 32토큰을 생성한다. 첫 후보 토큰을 포함해
13토큰 이상 생성한 뒤 다음 패턴이 새로 완성되면 해당 롤아웃을 종료한다.

| 패턴 | 의미 |
|---|---|
| `. ` | 마침표 뒤 공백 |
| `.\n` | 마침표 뒤 줄바꿈 |
| `.\t` | 마침표 뒤 탭 |
| `\n\n` | 빈 줄 |
| `\n-`, `\n*` | 목록 시작 |

패턴이 여러 토큰으로 나뉘어 생성되어도 감지한다. 13토큰 전에 이미
완성된 패턴은 나중에 종료 사유로 재사용하지 않는다. EOS와 추론 종료
마커는 최소 길이에 관계없이 즉시 종료한다. 단일 줄바꿈과 백슬래시
자체는 종료 조건이 아니다. 이 규칙은 분기 롤아웃에만 적용하며 본문이나
최종 답변을 조기 종료하지 않는다.

## 설정과 비교 실험

새 방법론의 진입점은
[`configs/bounded-entropy-sentence.json`](../configs/bounded-entropy-sentence.json)이다.
이 설정은 패키지 기본 설정에서 세 기능에 해당하는 키만 추가한다.
기존 main 기본 설정은 세 기능을 끈 상태로 유지한다.

```bash
uv run --frozen lost-tokens run \
  --config configs/bounded-entropy-sentence.json \
  --benchmarks aime25 --gpus 0 --arms baseline ours \
  --run-name bounded-entropy-sentence-aime25
```

세 기능의 설정 키는 `budget_forcing`, `min_branch_entropy`,
`rollout_early_stop`이다. 키를 생략하거나 `null`로 설정하면 해당 기능을
끈다. `baseline`에도 같은 budget forcing을 적용해 답변 예산을 맞춘다.
엔트로피 기준과 롤아웃 조기 종료는 분기를 사용하는 모든 arm에 적용된다.
출력 한도를 줄일 때는 강제 종료 위치와 답변 예약량도 함께 조정한다.

개별 기여를 평가할 때는 같은 문제·시드·본문 한도에서 세 기능을 하나씩
끄는 비교를 사용한다. 기존 README의 과거 점수는 원래 방법의 결과이며,
새 세 기능 조합의 성능으로 해석하지 않는다.

## 통합 범위

main의 메모리 이벤트 제한, 초기 분기 지연, TTL, 반복 방지, 체크포인트,
재개, 감사 및 평가 기능은 유지한다. 새 방법론 설정에서는 main의 선택적
메모리 제한·지연·TTL 기능을 켜지 않는다.

다른 브랜치의 수치 불일치 필터, 변수 앵커링, 메모리 포맷 변경,
태스크별 게이팅, 엔트로피 기반 동적 롤아웃 길이, GPU 임계값 조정,
Windows 호환성 변경은 포함하지 않는다. 독립 캐시, 코사인 필터와
선택된 롤아웃의 정확한 커밋 규칙은 main과 같다.

완료된 롤아웃과 강제 종료 토큰은 원자적 체크포인트로 보존한다.
재개는 저장된 호출을 재사용하고 원래 위치별 시드를 유지한다.
감사는 엔트로피 조건, 조기 종료 경계, 남은 추론 예산, 강제 종료 위치를
기존 토큰·메모리 재구성 검증에 추가한다.
